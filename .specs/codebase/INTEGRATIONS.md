# External Integrations

**Analyzed:** 2026-05-28

## Authentication

**Service:** Better Auth
**Purpose:** Email/password login, session management, Next.js handlers, cookies.
**Implementation:**

- Config: `src/infra/auth/server.ts`
- Browser client: `src/infra/auth/client.ts`
- Route handler: `src/app/api/auth/[...all]/route.ts`
- Session helpers: `src/infra/auth/session.ts`

**Configuration:**

- `BETTER_AUTH_SECRET`
- `BETTER_AUTH_URL`
- Better Auth Prisma adapter configured with provider `postgresql`

**Authentication:** Credential provider using email/password. Public signup is disabled with `emailAndPassword.disableSignUp: true`.

## Database

**Service:** PostgreSQL 17
**Purpose:** Persistent storage for users, sessions, accounts, verification records, invitations, subject fields, questions, and alternatives.
**Implementation:**

- Local service: `docker-compose.yml`
- ORM schema: `prisma/schema.prisma`
- Client: `src/infra/db/prisma.ts`

**Configuration:**

- `POSTGRES_DB`
- `POSTGRES_USER`
- `POSTGRES_PASSWORD`
- `POSTGRES_PORT`
- `DATABASE_URL`

**Authentication:** Database user/password through connection string.

## ORM

**Service:** Prisma 7
**Purpose:** Schema, migrations, generated client, and typed data access.
**Implementation:**

- `prisma.config.ts`
- `prisma/schema.prisma`
- generated client output: `src/generated/prisma`

**Configuration:** `prisma.config.ts` reads `DATABASE_URL` and migration path.

## API Integrations

### Better Auth HTTP API

**Purpose:** Auth endpoints for sign-in/sign-out/session flows.
**Location:** `src/app/api/auth/[...all]/route.ts`
**Authentication:** Better Auth session cookies.
**Key endpoints:** Generated by Better Auth via `toNextJsHandler(auth)`.

### Local Domain JSON APIs

**Purpose:** Admin and teacher workflows.
**Location:** `src/app/api`
**Authentication:** Better Auth session cookies, then route-level role checks via `hasRole`.
**Key endpoints:**

- `/api/invitations` for admin list/create.
- `/api/invitations/[invitationId]/cancel` for admin cancellation.
- `/api/invitations/accept` for public token acceptance.
- `/api/subject-fields` and `/api/subject-fields/[subjectFieldId]` for teacher subject-field CRUD.
- `/api/questions` and `/api/questions/[questionId]` for teacher question CRUD.

## Email

No production email provider dependency is implemented yet. Invitation delivery has an adapter boundary in `src/features/invitations/invitation-email.adapter.ts`; current delivery is suitable for console/test-style operation until SMTP/provider delivery is wired.

**Planned invitation configuration:**

- `APP_BASE_URL`: public application base URL used to build absolute invitation links.
- `INVITATION_EMAIL_DELIVERY`: delivery mode. Use `console` in local/test until SMTP/provider delivery is implemented.
- `INVITATION_EMAIL_FROM`: sender label/address for invitation emails.
- `SMTP_HOST`: optional SMTP host for future `smtp` delivery.
- `SMTP_PORT`: optional SMTP port for future `smtp` delivery.
- `SMTP_USER`: optional SMTP username for future `smtp` delivery.
- `SMTP_PASSWORD`: optional SMTP password for future `smtp` delivery.
- `SMTP_SECURE`: optional SMTP TLS flag for future `smtp` delivery.

## File Storage

**Service:** Supabase Storage
**Purpose:** Persistent storage for markdown question images uploaded from the teacher question editor.
**Implementation:**

- Feature storage port: `src/features/uploads/object-storage.ts`
- Upload service: `src/features/uploads/markdown-image.service.ts`
- Supabase adapter: `src/infra/storage/supabase-storage.adapter.ts`
- Upload route: `src/app/api/uploads/markdown-images/route.ts`

**Configuration:**

- `SUPABASE_URL`: Supabase project URL used server-side by the storage client.
- `SUPABASE_SECRET_KEY`: server-only secret key used by the API route/adapter. Never expose as `NEXT_PUBLIC_`.
- `SUPABASE_STORAGE_BUCKET`: existing bucket used for markdown images.
- `SUPABASE_STORAGE_PUBLIC_URL`: public base URL for persistent markdown image URLs.

**Authentication:** Application users authenticate through Better Auth. Upload authorization is enforced by the local API route before the server-side Supabase adapter stores files.
